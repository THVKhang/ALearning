1. Problem Statement

Task. Single-label image classification over 10 clothing categories. Input: one 28×28 grayscale image, a tensor of shape (1, 28, 28) (784 values once flattened). Output: one class index in {0, …, 9}. Prediction unit: one image.

Formally we learn a map f: R^(1×28×28) → R^10 producing unnormalized logits, and minimize the cross-entropy between softmax(f(x)) and the one-hot label over the training split. The predicted class is the argmax of the logits.

Motivation. Automatic garment categorization underpins catalogue indexing and inventory tagging in retail, where items arrive as photographs with no reliable text label.

Main difficulties. The images are low-resolution and uniformly centred, so colour and context give no help at all. Several categories share almost the same silhouette (Shirt, T-shirt/top, Pullover, Coat) and differ only in local texture and small details such as sleeve length or a button placket. That is what makes the dataset a useful testbed for comparing inductive biases: a model that consumes flattened pixels has no way to express local structure.

2. Dataset Description and EDA

Source. Fashion-MNIST (Xiao, Rasul & Vollgraf, 2017), published by Zalando Research under the MIT license and obtained through torchvision.datasets.FashionMNIST. 70,000 grayscale 28×28 images (60,000 official train, 10,000 official test), 10 classes, about 30 MB on disk in the original IDX format. Labels come with the published dataset; the group performed no labelling.

Dataset roles, as handbook Section 10 requires. Fashion-MNIST is the dataset for every main result on this page. MNIST is used for development and debugging only, selectable with --dataset mnist. No extension dataset such as CIFAR-10 was evaluated.

Preprocessing

ToTensor(), which scales pixels to [0,1], followed by Normalize(mean=0.2860, std=0.3530) using statistics measured on the training split itself. No augmentation is used (augment: false) for any of the five models, so the comparison is not confounded by it; a random-crop and horizontal-flip pipeline is implemented and can be switched on for an ablation. When augmentation is enabled it applies to the training subset only: the loaders are built from two separate views of the 60,000-image training set, so validation never sees augmented data. There are no invalid or missing annotations to handle.

Input tensor shape, one example batch after preprocessing: (128, 1, 28, 28), dtype float32, measured mean 0.0073 and std 0.9989 — confirming the normalization constants are the right ones for this split.

3. Methodology

Pipeline overview

Raw IDX files → ToTensor + Normalize → stratified 90/10 split → DataLoader (batch 128)
    → model (logits) → CrossEntropyLoss → Adam → argmax prediction
    → accuracy / macro-F1 / confusion matrix

Models

All five mandatory architectures of handbook Section 11.1, trained under one shared split and protocol. LSTM and GRU are both reported, which also covers the optional LSTM-versus-GRU comparison of Section 11.2.

CNN [Conv3×3(1→32) → BN → ReLU → MaxPool2] → [Conv3×3(32→64) → BN → ReLU → MaxPool2] → Flatten → Dropout(0.2) → Linear(3136, 10) 1×28×28 image, spatial structure intact 50,378
LSTM LSTM(input 28 → hidden 128, 1 layer) → last hidden state → Dropout(0.2) → Linear(128, 10) 28 row tokens of 28 pixels 82,186
GRU GRU(input 28 → hidden 128, 1 layer) → last hidden state → Dropout(0.2) → Linear(128, 10) 28 row tokens of 28 pixels 61,962
Transformer encoder Linear(28 → 128) + CLS token + learned positions → 2 × EncoderLayer(d_model 128, 4 heads, FFN 256, pre-norm, GELU) → LayerNorm → Linear(128, 10) 28 row tokens of 28 pixels 274,058

Loss. nn.CrossEntropyLoss for every model. All five output raw logits and no softmax is applied before the loss, because nn.CrossEntropyLoss already applies log-softmax internally; applying it twice would flatten the gradients. This was verified by searching the whole source tree for softmax calls and by checking that no model contains a softmax module.

Activation and regularization (MLP). The hidden layer uses ReLU, max(0, z). Without a nonlinearity the two stacked linear layers would collapse into a single linear map and the MLP would be mathematically identical to the baseline — the nonlinearity is the entire reason the extra layer can help. ReLU was chosen over sigmoid or tanh because its gradient is exactly 1 on the positive side and therefore does not shrink as it propagates backwards. Regularization is dropout at rate 0.2 on the hidden activations: a random fifth of the hidden units is zeroed at each training step, so the classifier cannot come to depend on any single unit. Dropout is inactive at evaluation time through model.eval(). No weight decay is used (weight_decay: 0.0).

Convolution, pooling and feature maps (CNN). A convolution layer slides a learned 3×3 kernel across its input and takes the weighted sum under the window. The same kernel is reused at every position, so a pattern such as a vertical edge is detected wherever it appears, and one output channel costs 3·3·Cin weights rather than one weight per pixel position as in a linear layer. With padding=1 the kernel leaves height and width unchanged, so all downsampling comes from the pooling layers. Each kernel produces one feature map, an image whose value at (i, j) measures how strongly that kernel pattern is present around pixel (i, j); the first block emits 32 such maps, the second convolves across all 32 at once and emits 64, so its kernels combine edges into corners, textures and then into sleeve, heel or strap shapes. MaxPool2d(2) keeps only the largest value in each 2×2 window, halving height and width: 28×28 → 14×14 → 7×7. It discards where inside the window the feature fired while keeping that it fired, which buys a little translation tolerance, cuts the activation tensor fourfold, and doubles the area of the original image the next kernel can see. BatchNorm normalizes each feature map over the batch, keeping the activation scale stable across blocks.

Timestep, input size and hidden representation (LSTM / GRU). A 28×28 image has no natural notion of time, so the sequence representation is an explicit choice: src/data/sequence.py offers rows, columns or patches, and both sequence models use rows, reading the garment top to bottom. The timestep is therefore one image row and there are 28 of them. The input size is the length of one token, channels × width = 28 values. The hidden representation is a state ht of 128 values rewritten at every step from the pair (xt, ht-1): a GRU does this with two gates, update and reset, deciding how much of the previous state to keep and how much of the new candidate to write; an LSTM adds a separate cell state ct and a third gate, so it can carry information along ct almost unchanged across many steps while the output gate controls what of it is exposed. Either way ht after the last timestep is a fixed-size summary of the whole image, and the classifier reads only that vector, not the per-timestep outputs. Note the contrast with the CNN: a convolution shares weights across space, while a recurrent cell shares them across time and must pass evidence from row 1 through 27 updates before it can affect the prediction.

Token embedding, positional encoding and attention (Transformer). The same 28 row tokens are used, so the Transformer and the recurrent models see identical input. One nn.Linear(28, 128) projects every token to a common width — the token embedding, or patch-embedding step: attention never sees pixels directly, only these projections. Because self-attention is permutation-invariant — shuffling the rows would permute the output and leave the summary unchanged — position must be supplied explicitly, so a learned parameter of shape (1, 29, 128), one vector per sequence slot, is added to the embedded tokens and trained with the model. A fixed sinusoidal table would also work; the learned version is used because the sequence length is small and constant, leaving nothing to extrapolate to. Each encoder layer then maps the sequence to queries Q, keys K and values V by linear projections. The score between token i and token j is the scaled dot product qi·kj/√dhead, and a softmax over j turns row i of the score matrix into weights summing to 1; the layer output at position i is that weighted sum of value vectors. So the output at row i is a mixture of every row, weighted by relevance to row i — a global receptive field after a single layer, where the CNN needs several pooling stages to span the image. Four such attention maps run in parallel over 32 channels each and are concatenated. A learned CLS token is prepended; it carries no pixel content, so everything it holds after the encoder was pulled in from the image tokens by attention, and the classifier reads that one position.

Metrics. Accuracy and macro-F1 as primary metrics, plus parameter count, training time, inference time and the confusion matrix. Macro-F1 averages the per-class F1 scores with equal weight, so a model that sacrifices one hard class to gain on easy ones is penalized — which accuracy alone would hide.

Strengths and limits. The linear model is convex in its parameters and trains to a reproducible optimum, but its decision boundary is a hyperplane over raw pixel intensities and cannot represent a statement such as "this region has horizontal texture". The MLP can represent nonlinear combinations of pixels, yet because it still consumes a flat vector it has no notion that two pixels are neighbours. The CNN adds exactly that notion and gets translation tolerance with it, at the cost of a fixed assumption that the useful structure is local. The recurrent models keep one spatial axis intact inside each token and destroy the other, and they must propagate evidence sequentially, which is a weaker spatial prior than convolution but a stronger one than a flat vector. The Transformer assumes the least — any token may attend to any other from the first layer — which is its strength on large datasets and its weakness here, because every relationship convolution supplies for free has to be learned from 54,000 images.

Self-implemented versus library code. Self-implemented: all six model definitions, the image-to-sequence conversion, the stratified splitting, the train/validation/test loops, checkpoint selection, early stopping, the metric wrappers, the timing instrumentation and all figures (everything under src/ and scripts/). Taken from libraries: torch and torch.nn layers — including nn.Conv2d, nn.LSTM, nn.GRU and nn.TransformerEncoderLayer — the optimizer and autograd; torchvision for the dataset download and the transforms; scikit-learn for f1_score and confusion_matrix; matplotlib for plotting; PyYAML for the configuration files. No pretrained weights are used anywhere, as Section 11.3 requires.

Experimental design

Hypothesis. Performance on Fashion-MNIST is governed less by parameter count than by how much spatial structure the input representation preserves, and the differences between architectures will concentrate on the four upper-body garments that share a silhouette and differ only in local texture — the classes the EDA identified before any model was trained.

Changed factor: the architecture and its input representation. Fixed factors: split, seed, preprocessing, batch size, optimizer, learning rate, epoch budget, early-stopping rule, checkpoint rule, hardware, software versions. Conclusion criterion: ordering by test macro-F1, read together with the parameter count and with the per-class gap between the upper-body group {Shirt, T-shirt/top, Pullover, Coat} and the remaining six classes. A model is only called better if it wins without a parameter advantage, or wins by more than the per-class spread.

6. Comparison and Discussion

  • Inductive bias beats raw capacity, and that is the main finding. The CNN wins with 50,378 parameters — 4.0× fewer than the MLP and 5.4× fewer than the Transformer — for +0.024 macro-F1 over the MLP. Convolution supplies two priors for free that every other model has to learn from 54,000 images: neighbouring pixels are related, and a feature means the same thing wherever it appears. At this dataset size that is worth more than parameters. The parameter ranking and the accuracy ranking are almost reversed.
  • Representation ordering predicts the result. Flattening destroys both spatial axes (linear, MLP); reading rows destroys one and keeps the other intact inside each token (LSTM, GRU, Transformer); convolution keeps both (CNN). The macro-F1 ordering follows that almost exactly, and the GRU beats the MLP — 0.9010 against 0.8902 — with 3.3× fewer parameters (61,962 against 203,530), which is the clean form of the argument: the gain comes from the representation, not from capacity.
  • GRU beats LSTM: +0.011 macro-F1 with 75% of the parameters. Over a 28-step sequence the separate cell state of the LSTM has no long-range dependency to protect, so its third gate only adds parameters to overfit with. On this task the simpler cell is the better one. This is the optional Section 11.2 comparison.
  • The Transformer is the weakest non-linear model despite having the most parameters. It assumes the least — self-attention treats the 28 rows as an unordered set and must learn adjacency through the learned positional encoding — and its upper-body gap (0.1707) is the widest of any non-linear model. Its error profile shows the same thing in detail: 113 Shirt-as-Pullover confusions against 75 for the CNN, and 98 Coat-as-Pullover against 45. The gap between CNN and Transformer is not spread across the dataset; it is almost entirely these local-texture classes. This is the expected ordering at this scale and is not evidence against attention architectures in general.
  • The epoch budget, not the architecture, limits two of the models. The MLP and the Transformer both picked epoch 15 of 15 with validation macro-F1 still rising. The Transformer is the one most penalised by a short fixed schedule, since attention models trained from scratch typically need the longest one. A conclusion of the form "CNN beats Transformer on Fashion-MNIST" is therefore not supported by this table; what is supported is "CNN beats Transformer under an equal and short epoch budget".
  • The two inference columns answer different questions. The model-only column times the forward pass with batches already on the GPU, and it is monotone in computation as it should be: linear 0.0005 < MLP 0.0016 < GRU 0.0051 < LSTM 0.0086 < CNN 0.0097 < Transformer 0.0152 ms/image. The end-to-end column adds the data loader and collapses to 0.16–0.24 ms/image for every model, because with num_workers: 0 loading costs 15× to 400× the forward pass. Deployment throughput at this scale is a property of the data pipeline, not of the architecture; only the model-only column compares models. The M1 Draft page reported a single loader-bound figure, which made the CNN look faster than a single linear layer; that measurement has been replaced.
  • The training-time column is not a model property either. It is loader-bound for the same reason and is not even monotone in model cost — the LSTM run averaged 11.3 s/epoch against 21.7 for the linear model. Run-to-run machine noise exceeds the real difference: during the MLP run the EDA notebook was executing on the same machine, visibly shortening its epochs 5–7 in history.json. Models must not be ranked by this column.
  • What still cannot be concluded. Each model ran once at a single seed, so no variance estimate exists and differences of a few thousandths are not interpretable — the MLP-versus-LSTM gap of 0.0004 is well inside that range and those two should be read as tied. No model received hyperparameter tuning, and no parameter-matched or compute-matched comparison was run, so this table compares six specific configurations rather than six architecture families.

The better the model, the larger the share of its errors that falls inside the upper-body group — 59.9% for the linear baseline rising to 64.7% for the CNN — while cross-group errors drop from 7.8% to 4.0%. Architectures fix the easy structure first and leave the same residue behind.

One confusion resists every architecture. Shirt predicted as T-shirt/top stays in a band of 106–161 images across all six models while total errors nearly halve; the CNN makes 146 of them, more in absolute terms than the linear baseline makes. Shirt is the worst class for every model, from F1 0.5999 to 0.7399, and even the best model leaves it 0.23 F1 below its own average. The distinguishing evidence between a short-sleeved shirt and a T-shirt is a collar or a button placket a few pixels wide, which at 28×28 grayscale is often simply not present in the image. This is label ambiguity in the dataset, not a capacity limit, and scaling a model up is unlikely to remove it.

Hypothesized causes, by group. Shirt and T-shirt/top overlap in both directions, which marks a genuinely shared class boundary rather than a bias toward one label. Pullover and Coat are both long-sleeved and closed-fronted at this resolution, where a coat opening is often only a faint vertical line — the CNN halves this group, from 223 to 94, which is the clearest single demonstration that local texture is what convolution adds. Long-sleeved shirts fall inside the pullover and coat silhouette, and notably the Transformer is worst of all six on that group (213, 18.5% of its errors), consistent with having no local prior.

Improvement ideas. (i) Train the MLP and the Transformer past 15 epochs, since neither converged. (ii) Give the Transformer a patch representation instead of rows — src/data/sequence.py already supports 7×7 patches, which would hand it a weak locality prior at no architectural cost. (iii) Test a two-stage classifier, coarse group first and then within-group, and report it as an optional extension rather than a core result. (iv) Report multiple seeds, since several gaps here are small enough to need a variance estimate.

8. Limitations and Conclusion

Data limitations. Fashion-MNIST is 28×28, grayscale, centred and background-free, and roughly half of every image is exactly black. Conclusions about inductive bias drawn here do not transfer unchanged to natural images, where scale, pose, lighting and background all vary — in particular, the ordering CNN above Transformer is characteristic of small low-resolution datasets and routinely reverses at scale. The dataset is also a curated research benchmark, so its class balance is not representative of a real catalogue.

Method limitations. One configuration per architecture, chosen as a plain default rather than tuned, and no parameter-matched or compute-matched comparison. The five models differ by 35× in parameter count, so the table compares these six runs and not the architecture families in general.

Experimental limitations. One seed per model and therefore no variance estimate; an epoch budget that the MLP and the Transformer had not saturated; training-time figures that measure the data loader more than the model; and a single dataset, with no robustness, augmentation or interpretability ablation.

Conclusion. Across all five mandatory architectures under one split and one protocol, test macro-F1 ranges from 0.8441 to 0.9145, and the ordering is governed by how much spatial structure each input representation preserves rather than by parameter count: the CNN is best with 4× fewer parameters than the MLP and 5.4× fewer than the Transformer, and the GRU beats the MLP with 3.3× fewer. The differences are concentrated, by a factor of 3.5, in the four classes the EDA had already identified as sharing a silhouette and differing in local texture — which is the concrete form the inductive-bias argument takes on this dataset. The residual errors are dominated by one confusion, Shirt against T-shirt/top, that no architecture here reduces, indicating a limit of the data rather than of the models.

Future work. A loader-independent training-time protocol; multiple seeds reported as mean ± standard deviation; longer schedules for the two unconverged models; a patch representation for the Transformer; a matched-parameter comparison; and an augmentation ablation.
