1. Problem Statement

  • Task Goal: Monocular Depth Estimation — predict physical distance (in metres) from camera per pixel from a single 2D RGB photo.
  • Key Challenge: Scale ambiguity in 2D photos (a small nearby object vs. a giant distant object can take up identical pixel sizes). Model must learn visual perspective, texture gradients, and boundary cues.
  • Data Scope: Evaluated on both Indoor (1–9m close-range) and Outdoor (up to 100–200m long-range) scenes. Ground truth is measured by LiDAR laser scanners. Missing laser reflections (sky, glass, sharp edges) use a validity mask (1 = valid depth, 0 = ignore).

2. Dataset Description & Preliminary EDA

2.1 Dataset Overview & Processing Workflow

  • Source Dataset: DIODE — Dense Indoor and Outdoor DEpth (Vasiljevic et al., 2019), diode-dataset.org. Obtained through a Kaggle mirror of the official release. The upstream release totals 26,229 RGB images (train 8,574 indoor + 16,884 outdoor; val 325 indoor + 446 outdoor), which matches the mirror we downloaded.
  • Version: the original 2019 DIODE release, obtained from the Kaggle mirror artemmmtry/diode-a-dense-indoor-and-outdoor-depth-dataset, Kaggle Version 8 (199.89 GB, last updated two years ago). Not DIODEv2: the mirror holds 26,229 images, exactly the 25,458 training plus 771 validation images of the 2019 release, and its data sources contain only train/ and val/.
  • License: MIT, and consistent at both levels, which was checked rather than assumed: the upstream release states MIT on diode-dataset.org and in the official devkit repository diode-dataset/diode-devkit, and the Kaggle mirror we downloaded declares MIT in its own License field. The mirror therefore imposes no terms beyond the upstream licence, and redistribution of a derived subset is permitted provided the citation below is kept.
  • Citation: I. Vasiljevic, N. Kolkin, S. Zhang, R. Luo, H. Wang, F. Z. Dai, A. F. Daniele, M. Mostajabi, S. Basart, M. R. Walter and G. Shakhnarovich. DIODE: A Dense Indoor and Outdoor DEpth Dataset. CoRR abs/1908.00463, 2019.
  • Sample Volume: 7,195 RGB–Depth pairs (4,995 train, 1,100 val, 1,100 test across 15 scenes).
  • Sample Modality: Each sample consists of an RGB image, a high-precision laser depth map in metres, and a binary validity mask indicating measured laser reflections.
  • Processing Rule: Raw data is loaded dynamically during training via PyTorch DataLoaders; raw data files are kept local and excluded from repository version control.

2.2 Data Splitting Strategy (Scene-Level Split)

  • Leakage Prevention: Split strictly by Scene (room / location), not by individual image. Photos from the same room cannot appear in both train and test.
  • Split Ratio: ~70% Train / 15% Val / 15% Test (seed 42). Verified 0% scene overlap across splits (see scenes_used.csv).
  • Sampling Rule: Max 700 images per indoor scene, max 400 per outdoor scene (seed 42). Cap spreads the subset across 15 scenes instead of exhausting one large scene.
  • Note: All three splits come from the official DIODE training partition (no public test set is available), so our numbers are not directly comparable to published DIODE benchmarks.

2.3 Visual Inspection & Data Characteristics

  • Visual Alignment: Nearby ceiling lamps and pipes display in cool blue; far background walls shift to dark red. Outdoor paths gradually transition from blue to red (~40–50m).
  • Edge Noise (Edge Bleeding): Indoor invalid pixels appear mainly as thin boundary outlines around sharp object contours where laser reflection drops.
  • Outdoor Sky Region: Sky, fine branches, and objects beyond sensor range are masked as invalid (e.g. crane photo is mostly sky, leaving 6.9% valid pixels).

3. Methodology

3.1 Preprocessing Pipeline

  • Image Resizing: 1024×768 → 384×288 (RGB resized with bilinear; depth & mask with nearest-neighbour to avoid mixing in invalid zero values).
  • RGB Normalization: Scaled to [0, 1] + standard ImageNet mean/std normalization.
  • Depth Target: Kept in true physical metres; invalid pixels and depth outside 0.6–50m (indoor) / 0.6–200m (outdoor) are masked out in both loss and metrics.
  • Augmentation: Synchronous Random Horizontal Flip (p = 0.5) applied simultaneously to RGB, depth, and mask.

3.2 Baseline & Pretrained Models

  • Baseline Model: Small U-Net (4 levels, 32→512 channels, 7.76M params) trained from scratch. Predicts log-depth, output = exp(·) in metres. Loss: masked SILog (Eigen et al., 2014, λ = 0.5).
  • Pretrained Model: MiDaS_small (EfficientNet-Lite3 encoder, 21.3M params). Outputs relative inverse depth (unknown scale and shift).
  • MiDaS Fine-tune Loss: masked scale-and-shift-invariant (SSI) loss from the MiDaS paper (Ranftl et al., 2020): prediction and 1/GT are each normalised per image (median, mean abs deviation), then L1. Fits the relative output, unlike the L1 placeholder used in the M1 speed benchmark.
  • Alignment for Evaluation: per image, least-squares scale s and shift t so that s·pred + t ≈ 1/GT on valid pixels, then depth = 1 / (s·pred + t), clipped to the domain cap. The U-Net is reported raw (metres) and with the same alignment for a fair comparison.

3.3 Evaluation Metrics

  • Abs Rel (main metric): mean(|d − d*| / d*) → lower is better (↓).
  • RMSE: sqrt(mean((d − d*)2)) in metres → lower is better (↓).
  • δ1: % of valid pixels with max(d/d*, d*/d) < 1.25 → higher is better (↑).
  • Computed per image on valid pixels only, then averaged over images; reported for indoor, outdoor and overall. Predictions are clipped into the valid range instead of being dropped, so bad pixels still count.
  • Sanity check: feeding GT as the prediction gives Abs Rel = RMSE = 0 and δ1 = 100%; feeding 1/GT scaled and shifted through the alignment recovers GT (tests/test_metrics.py).

6. Comparison and Discussion

  • Full fine-tune is best overall (AbsRel 0.290) and clearly on indoor: 0.132 → 0.091 vs. zero-shot, δ1 84% → 92%. This matches the expectation that it beats both zero-shot and the scratch baseline.
  • Frozen encoder is close (0.299 overall, 0.106 indoor) with half the VRAM (1.17 vs 2.42 GB) and ~15% shorter training. The overall gap (0.009) comes from indoor only; outdoor is the same. With 1 seed we cannot say if this gap is bigger than seed noise → 3 seeds in the Final.
  • U-Net baseline: raw AbsRel 0.671 is mostly a scale error. The val indoor room is much closer than the train rooms (median 1.3 m vs 2.6 m) and the model predicts train-like distances (Figure 6, row 2). With alignment it drops to 0.338 (indoor 0.165), still worse than MiDaS zero-shot. Val Abs Rel is very noisy across epochs and the best epoch is 13 of 40, while train loss keeps going down → overfitting to the 11 train scenes.
  • Outdoor does not improve for any model (~0.64). Fine-tuning helps indoor but not the single outdoor val scene (see Section 7).

  • Indoor: fine-tuning gains come from near pixels (98% of indoor pixels). The few mid-range pixels (doorways, hallways >5 m) stay bad (~0.6) for every model and get slightly worse after fine-tuning.
  • Outdoor range compression: after alignment, near ground is predicted too far (AbsRel ~0.95) and far trees too close (δ1 < 1%). The predictions barely correlate with 1/GT on this scene, so the best scale/shift squeezes everything toward the middle.
  • Is it a pipeline bug? (checked, scripts/report/outdoor_check.py): MiDaS zero-shot on 25 images per outdoor scene gives Abs Rel 0.36–0.55 on the 6 train scenes and 0.55 on the test scene, but 0.68 on val scene 00017 (rank correlation with 1/GT 0.14 vs ~0.45 elsewhere). The same code gives 0.09–0.13 indoor, so outdoor is hard in general and the val scene is the hardest one. Dropping pixels next to invalid ones lowers val outdoor Abs Rel from 0.68 to 0.50, so thin branches and noisy GT edges are a big part of it. A log-space alignment was worse (0.89), so the alignment choice is not the cause.
  • Thin structures: val outdoor is one forest (scene 00017). GT is made of thin branches at very different depths with sky in between (Figure 6, rows 4–6); all models output smooth maps and miss them. Part of this is GT noise on leaves and edges.
  • U-Net artifacts: grid / checkerboard pattern from the transposed-conv upsampling, and blurry object borders.
  • Next (Final): also report the test split (other outdoor scene), split errors by object edges vs. flat regions, and try robust (median-based) alignment to see how much of the outdoor error is the alignment itself.

8. Limitations and Conclusion

8.1 Dataset & Pipeline Limitations

  1. Val and test each have only 1 indoor scene and 1 outdoor scene (val outdoor = scene 00017, a forest), so val numbers depend heavily on those two scenes.
  2. Outdoor val has higher sky/invalid pixel rate (~44% vs ~30% in train).
  3. Laser ground truth has noise at sharp object edges, leaves and glass (edge bleeding).
  4. DIODE only has upward/level camera angles (000–050); this is a property of the original dataset, not of our subset.
  5. Images are resized from 1024×768 to 384×288, which smooths fine details like wires and thin branches.
  6. All three splits come from the DIODE training set (no public test set available), so results are not directly comparable to published DIODE benchmarks.
  7. Draft results use 1 seed per config; differences of ~0.01 Abs Rel are not yet meaningful.

8.2 M2 Draft Conclusion

Evaluation tools are tested (metrics, alignment, reproducible seeding). Fine-tuning MiDaS_small beats both zero-shot MiDaS and the scratch U-Net, mostly on indoor scenes; freezing the encoder costs ~0.015 indoor Abs Rel but halves VRAM. Outdoor val (one forest scene) is the main failure case for all models. In progress for M3: 3 seeds per config, test-split numbers, deeper error analysis.
