1. Problem Statement

Monocular depth estimation is the task of predicting the physical distance (in metres) from the camera for every single pixel in a standard 2D RGB photo. It is an essential capability for mobile robotics, autonomous navigation, and 3D reconstruction.

The key challenge is that a single 2D photo has infinite depth ambiguity — a small object nearby and a huge object far away look identical in pixel dimensions. The model must learn complex visual cues like visual perspective, texture gradients, object boundaries, and atmospheric blur to infer scale.

In this assignment, we evaluate models across both indoor (close-up objects, 1–9m range) and outdoor (wide perspectives, up to 100–200m range) scenes. Ground-truth depths are captured by a high-precision LiDAR laser scanner. Areas without laser reflections (such as open sky, glass windows, or sharp edges) are represented with a binary validity mask (1 = valid depth, 0 = ignore), allowing us to compute loss and metrics strictly over valid pixels.

ComponentSpecification
Input DataSingle RGB image, shape 3 × 288 × 384 (H × W)
Target OutputPer-pixel depth map in metres, shape 1 × 288 × 384
Ground TruthLaser depth map d* and binary mask m (1 = valid pixel, 0 = invalid)
Task ObjectiveTrain neural network fθ(x) to estimate per-pixel depth, minimizing loss over valid pixels (where m = 1)

2.2 Data Splitting Strategy (Scene-Level)

To prevent data leakage, we split our dataset strictly by scene rather than picking random individual images. In DIODE, a single scene contains dozens of photos taken inside the same room or outdoor space. If images from the same room were shared between training and testing, the model could easily memorise room layouts.

By placing entire scenes into separate splits with fixed random seed 42, we achieve a clean ~70 / 15 / 15 split ratio with zero scene overlap between train, val, and test.

2.3 Visual Sanity Inspection

  • Depth predictions correspond accurately to visual scene structures: nearby ceiling lamps and pipes display in cool blue, while far background walls shift to dark red.
  • Indoor invalid pixels primarily occur as narrow border outlines around sharp edges (known as edge bleeding in laser sensors).
  • Outdoor invalid pixels map to open sky, thin tree branches, and distance limits beyond the sensor range.

3. Methodology

3.1 Preprocessing & Data Pipeline

  • Image Resizing: Resized from original 1024×768 down to 384×288 (H × W) to fit local VRAM limits.
  • RGB Normalization: Scaled to [0, 1] range and normalized using standard ImageNet mean `[0.485, 0.456, 0.406]` and std `[0.229, 0.224, 0.225]`.
  • Depth Targets: Preserved in true physical metres. Invalid pixels (mask = 0, NaNs, depth ≤ 0, or depth > 50m/200m cap) are masked out.
  • Data Augmentation: Synchronous random horizontal flip (p = 0.5) applied simultaneously to RGB, depth, and validity mask.

3.2 Baseline Model: Lightweight U-Net

We implement a convolutional U-Net architecture (encoder–decoder with skip connections) trained from scratch on our DIODE subset. The model outputs depth in metres using a masked Scale-Invariant Logarithmic (SILog) loss function.

3.3 Pretrained Backbone: MiDaS Small

We adopt MiDaS Small (intel-isl/MiDaS with EfficientNet-Lite3 backbone, ~21.3M parameters). For fine-tuning, the network outputs inverse depth, converted to absolute depth via `depth = 1 / output`, and optimized using masked SILog loss.

8. Limitations and Conclusion

8.1 Dataset & Pipeline Limitations

  1. Scene Diversity in Test Set: Validation and test sets each contain only 1 indoor scene and 1 outdoor scene. Performance reflects accuracy on these specific environments rather than all possible real-world settings.
  2. Indoor Scale Shift: Test indoor scenes feature smaller rooms (median depth 1.8m) than training scenes (median 2.6m), which contains a large indoor atrium.
  3. Outdoor Sky Invalid Ratio: Outdoor validation images have ~47% invalid pixels (mostly sky) compared to ~31% in training.
  4. Sensor Edge Bleeding: Laser scan ground truth contains slight boundary noise around sharp object contours.
  5. Camera Angle Restriction: DIODE contains only upward and level camera angles (vertical tilt 000–050). The trained model may not generalize well to downward-facing cameras (e.g., ground robots or downward drones).
  6. Resolution Trade-off: Downsampling to 384×288 reduces VRAM usage but smooths out fine structures like thin poles and distant object outlines.

8.2 M1 Conclusion

Our initial analysis confirms that the local 7,195-sample DIODE subset is clean, properly split by scene, and well suited for depth estimation benchmarks. Hardware benchmarking on our RTX 4060 GPU confirms that full fine-tuning runs efficiently (~1 min/epoch with AMP), making our proposed controlled experiment lightweight and completely achievable within 6–8 local GPU hours.
